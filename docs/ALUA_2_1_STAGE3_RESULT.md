## 3. Назначение 50 × 30

Порядок учитывает диагностический difficulty, CEFR, тематические группы/тему, priority, source_line. Без диагностики — A1 → A2 → B1 → B2 → C1. Для B2 начало — B2, затем B1/C1 и базовое покрытие; каталог всё равно проходится целиком. Заголовок дня складывается из двух преобладающих тем. Один день может пересекать несколько тем.

Программа хранит только ID, заголовки и прогресс; тексты не копируются на learner. Ровно 50 последовательных срезов по 30, каждое ID ровно один раз. Пока ни одна позиция курса не обработана, результат диагностики может изменить стартовый порядок. После первого действия порядок заморожен. Это 50 учебных дней, без обещания результата C1.

## 4. Два learner

`study_programs.learner_id` — PK/FK к существующим profiles. Все чтения и записи используют существующую authenticated identity. Обе программы независимы; одинаковая диагностика может дать одинаковый порядок, но никогда не общий прогресс. Клиент дополнительно отправляет learner_id, чтобы запоздалая очередь предыдущего профиля не применялась к новому после переключения.

## 5. Прогресс и временный offline

В программе хранятся introduced timestamps по ID и локальные даты завершения дней. Сервер принимает новую карточку только на очередной позиции доступного дня. Пропущенные даты не меняют текущий день. Следующий день открывается после календарной даты завершения предыдущего в Asia/Almaty. Backlog ничего не блокирует.

SwiftUI показывает 30 карточек по одной, делает паузу после 10/20, предлагает короткую проверку и продолжение. После закрытия открывается первая необработанная карточка. Today и Learn используют один store.

Перед отправкой действие с UUID и локальный прогресс атомарно записываются в Application Support, отдельно для learner. Очередь ограничена 100 действиями. Удаление — только после подтверждения сервера; повторная отправка сохраняет UUID. Повтор — при входе, возвращении приложения, ручном обновлении и каждые 15 секунд, пока экран курса активен. При ошибке чтения хранилище не затирается. Это кеш текущего урока/личной книги, не полноценный offline-first или фоновый синхронизатор.

После Дня 50 данные остаются доступны.

## 7. Повторение и старая история

Использован `DeterministicVocabularyScheduler`, `VocabularyReviewState`, существующие `canonical_vocabulary_states` и `review_responses`. Знакомство назначает повторение через сутки без увеличения review_count. «Не знаю» приближает повторение до 30 минут и не даёт mastery. «Уже знаю» ставит verification_pending. В повторении сервер сравнивает выбранный перевод с ожидаемым; неправильный ответ/«Не знаю» даёт AGAIN. UI предлагает порции до 10 и повтор одной карточки из книги.

`retained` требует успешных повторений, разделённых минимум сутками; немедленные повторные правильные нажатия не подтверждают долговременное знание. Статусы due/hidden вычисляются отдельно. Повторение не меняет число новых карточек.

357 связей построены только по уникальному точному term + полному русскому значению (casefold). Номера строк разных исходных словарей не приравнивались к source_line нового корпуса. Нечёткие и неоднозначные совпадения не объединяются. Для связанного нового ID используется прежний ключ SRS/preference; старые events не переписываются. Несвязанный старый контент остаётся в книге отдельным ID. При первом создании программы импортируются факты открытия/ответов из legacy learning events и явные known/unknown/hidden preferences в кандидаты SRS без начисления успешных повторений. Существующие review states доступны сразу.

Legacy API daily packs сохранён для совместимости Stage 2 и существующих consumers. Основной интерфейс новых слов Today/модуль Vocabulary переключён на Stage 3; grammar curriculum и упражнения сохранены. Этот этап не перерабатывает WidgetKit/legacy напоминания.

## 8. Идемпотентность

`study_events` имеет составной PK `(learner_id,event_id)`. Повтор UUID с тем же payload возвращает saved, с другим — 409. Строка программы блокируется `FOR UPDATE`, затем SRS-state; прогресс, preferences, event и SRS сохраняются одной транзакцией. Review-response ID проверяется также против существующей таблицы review responses. Повтор обработки карточки не увеличивает число introduced. Ошибка транзакции откатывает все её записи. Проверены конкурентные одинаковые запросы.

## 12. Ограничения и открытые вопросы

- Независимая человеческая проверка лексики ещё нужна; базовый A1/A2 сегмент ограничен исходным набором.
- Контроль понимания — выбор перевода, без оценки свободной речи/IELTS score.
- Локальная очередь работает при активном приложении; удаление приложения/данных устройства не является поддерживаемым offline-сценарием. При серверном 409 очередь сохраняется с ошибкой, автоматического конфликтного merge нет.
- Legacy API/напоминания/WidgetKit сохраняют прежние контракты; их полная унификация с курсом не входит в визуальную интеграцию этого этапа.
- Для обновлений каталога нельзя удалять ранее выданные ID или менять существующие legacy_links: назначенные программы и SRS опираются на них. Произвольная замена каталога другой семантикой не поддерживается; будущий импорт обязан сохранять эти контракты.
- Проверки подтверждают backend сценарий и клиентскую durability; физический end-to-end на двух подписанных iPhone ещё необходим перед будущей установкой.
