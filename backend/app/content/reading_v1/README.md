# Alua Academic Reading Dataset v1

Локальный канонический контент для следующего backend-этапа. Рабочие API, база данных и iOS не изменялись. Исходные TXT/PDF остаются в корне репозитория.

## Файлы и загрузка

Начните с `manifest.json`: `books`, `exams`, исходный `source_test_number`, порядковый `test_ordinal`, относительные `exam_path`, `answer_key_path`, assets, SHA-256 и статусы. Cambridge 12 использует исходные Test 5–8; ordinal остаётся 1–4. Все пути внутри manifest относительны этому каталогу.

`exams/` — публичные passages и задания. `answer_keys/` — **закрытые серверные ключи**. Не отдавать весь каталог как static files, не включать answer keys в iOS bundle. Даже manifest содержит служебные пути ключей: для клиента строить отдельный каталог разрешённых экзаменов без закрытых полей.

`schema/reading_exam.schema.json` и `reading_answer_key.schema.json` используют Draft 2020-12, обязательные поля и `additionalProperties: false`. IDs вопросов имеют вид `cambridge-18-test-01-q-01` и не зависят от позиции в массиве. Группа содержит самостоятельные вопросы и общий контекст; диапазон — реальные оцениваемые позиции.

`content` сохраняет настоящие текстовые абзацы, заголовки и метки параграфов. `content_blocks` содержит rich text с numbered blanks, списки, таблицы и изображения. `representation: source_image_with_inputs` означает: показывать исходное задание из assets и отдельные numbered inputs. Rich text остаётся доступен для поиска и последующего улучшения; не выводить его повторно поверх того же изображения. Для встроенного пропуска `prompt` может содержать общий контекст группы: отображать shared context один раз.

Сложные таблицы, схемы и повреждённая OCR-разметка сохраняются как изображения задания с привязанными inputs. Там, где TXT явно задаёт строки/поля, также есть семантическая таблица. Геометрия остальных таблиц не угадывается. Часть individual options пока доступна через исходное изображение: см. `options_via_source_image` в audit. Это конкретное ограничение typed content, не потеря исходного задания.

## Assets и источник

`assets/` содержит PNG без потерь, рендер 2.5 пикселя на PDF point (180 dpi). Каждый asset хранит исходный PDF, **однобазовую PDF-страницу**, `crop_box` в PDF points с началом сверху слева, размеры, масштаб и хеш. Многостраничная таблица имеет несколько assets в исходном порядке. Проверки существования файла недостаточно: `extracted_needs_visual_review` требует проверки границ и читаемости. Не выводить image как source-verified автоматически.

`source_reference` содержит TXT-файл и исходные номера строк, PDF и страницы. Для группы страницы могут быть диапазоном passage, если точная страница не установлена; точная страница вырезки хранится в asset. Пустой `pdf_pages` у ключа означает, что локальная страница ключа ещё не установлена, а не отсутствие ключа. Cambridge 09 прямо указывает внешний источник ключей, отсутствующий в предоставленном PDF; сетевые копии не загружались.

`corrections.jsonl` — подтверждённые исправления с прежним/новым фрагментом и PDF evidence. Входные исправления находятся в `backend/scripts/reading_dataset/source_edits.json`; применяются только в памяти, с проверкой точного старого фрагмента. `paragraph_labels.json` содержит визуально подтверждённые метки секций с точными текстовыми якорями; неизвестные метки блокируют соответствующий экзамен. `source_question_range` хранит диапазон из оригинальных инструкций или null, если диапазон явно не установлен; validator сверяет его с привязкой вопросов. `source_reviews.json` хранит ограниченные визуальные проверки и ручные границы схем. Эти проверки не являются подтверждением всего экзамена. Новое спорное место: сначала локальный рендер страницы, затем визуальная сверка, затем узкое исправление и регенерация. Нечитаемый фрагмент остаётся в audit; не исправлять по смысловой догадке.

## Генерация и валидация

Python 3.12+, системный `tesseract` с английским языком; зависимости только для сборки перечислены в `backend/scripts/reading_dataset/requirements.txt`. Runtime backend может читать JSON и использовать стандартную библиотеку в `grading.py` без PDF/OCR-зависимостей.

Из корня репозитория (при первом запуске зависимости можно поставить из локального uv cache):

```sh
uv venv /tmp/alua-reading-env --python 3.12
uv pip install --offline --python /tmp/alua-reading-env/bin/python -r backend/scripts/reading_dataset/requirements.txt
/tmp/alua-reading-env/bin/python backend/scripts/reading_dataset/generate.py
/tmp/alua-reading-env/bin/python backend/scripts/reading_dataset/validator.py
```

`generate.py` строит отдельный staging-каталог, проверяет все артефакты, затем заменяет dataset; при ошибке прежний dataset сохраняется. Не запускайте параллельные генераторы в один output. Возможен `--output /tmp/alua-reading-rebuild` для независимой сборки/сравнения. `engine.py` — parser core; его CLI также использует безопасную транзакционную обёртку. OCR-кэш находится отдельно, в системном temp `alua-reading-pdf-cache/<pdf-hash>/`; в канонический dataset он не попадает. Временные QA-скрипты не нужны для повторной генерации.

Validator проверяет 18×4, три passages, позиции 1–40 без дублей, привязки IDs и keys, обе схемы, input types, assets и их PNG/hash/размеры, grading groups, manifest hashes, исходные source hashes и защиту release. **Успех artifact validation не означает готовность контента к публикации.** `audit_report.json` содержит структурные и редакционные проблемы отдельно.

## Контракт FastAPI / PostgreSQL

Импортировать manifest и JSON транзакционно, без повторного разбора TXT. Версию хранить как `(dataset_version, content_revision)`, а экзамен — по стабильному ID. Хеши проверять до импорта; опубликованные версии не изменять. Сессию пользователя привязывать к точной версии и ревизии. В PostgreSQL подходят отдельные content revisions, exams/passages/groups/questions и закрытая таблица keys; JSONB можно использовать для typed blocks. Этот этап не создаёт таблиц, миграций или routes.

Разрешать прохождение только при `content_status == ready`, `source_verified == true` и полной source verification текста, вопросов и ключей. Сейчас полная source verification ни для одного экзамена не заявлена; `needs_review` предназначен для редакторского QA. `blocked` содержит критическую неоднозначность, включая исходную ошибку labels Cambridge 20 Test 3 Q22–23 (PDF p.94). Не исправлять её перенумерацией A–F без подтверждённого ключа/источника.

Для оценки использовать `backend/scripts/reading_dataset/grading.py::grade_exam(exam, key, responses)`. Responses — объект `{question_id: string}`; UI multi-select раскладывает выбор по IDs группы. Backend сам загружает приватный key той же версии; клиент ключ не присылает. Функция проверяет release, IDs и версии, считает результат из 40 и ошибки по типам. `allow_unreleased=True` — только для локального QA, никогда не включать по клиентскому параметру.

Нормализация ограничена Unicode NFKC, регистром, пробелами, апострофами и разделителем тысяч в числах. Альтернативы/UK–US spelling берутся только из официальной записи. Скобки разворачиваются как optional words, slash — как официальные альтернативы. Для `unordered_unique` ключ хранит `expected_units` — отдельные правильные элементы и их варианты. Применяется максимальное сопоставление с этими элементами: повтор одной буквы или двух вариантов одного слова даёт максимум один балл. `unordered_parts` требует все части одного ответа, в любом порядке, и даёт один балл. Fuzzy matching, произвольные synonyms, blanket removal punctuation и неподтверждённые сокращения не применяются.

`duration_seconds` = 3600, `module` = academic_reading. Band conversion в этом этапе не задана: результат — корректные позиции из 40.
